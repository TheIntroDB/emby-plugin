# Issue 28 native marker detection capability

Date: 2026-08-17
Issue: https://github.com/TheIntroDB/emby-plugin/issues/28
SDK package: `MediaBrowser.Server.Core` 4.9.1.90
Validated runtime version context: Emby 4.9.5.0

## Required contract

A safe contribution runner must provide all of these through documented public plugin APIs:

1. target exactly one selected item
2. await exact success or failure of that invocation
3. return an opaque run identity plus the exact markers generated by that invocation

A chapter before and after delta, time-window correlation, broad scheduled task, reflection into private server types, or loopback HTTP call is not accepted.

## Public SDK inspection

The public assemblies from the restored 4.9.1.90 package were loaded and their public method signatures inspected.

### `MediaBrowser.Model.Tasks.ITaskManager`

Documented public queue methods operate on registered scheduled tasks or generic task types:

- `QueueScheduledTask<T>()`
- `QueueScheduledTask(IScheduledTask, TaskOptions)`
- `CancelIfRunning<T>()` and `CancelIfRunningAndQueue<T>()`
- `AddTasks(IEnumerable<IScheduledTask>)`
- `ScheduledTasks`

`IScheduledTask.Execute(CancellationToken, IProgress<double>)` awaits the scheduled task as a whole. `TaskOptions` and `IScheduledTask.Execute` have no selected media item argument and return no marker output. A native scheduled task may process unrelated media.

### `MediaBrowser.Controller.Entities.BaseItem`

Public refresh methods include:

- `RefreshMetadata(CancellationToken)` returning `Task`
- `RefreshMetadata(MetadataRefreshOptions, CancellationToken)` returning `Task<ItemUpdateType>`

They do not expose a native marker-detector run identity or exact generated chapter receipt.

### `MediaBrowser.Controller.Providers.IProviderManager`

- `RefreshSingleItem(BaseItem, MetadataRefreshOptions, BaseItem[], LibraryOptions, CancellationToken)` is item-scoped and awaitable, but it is a metadata refresh returning only `ItemUpdateType`.
- `QueueRefresh(long, MetadataRefreshOptions, RefreshPriority[, bool])` queues work without item-bound detector completion or output.
- `WaitForRefreshQueue(IProgress<double>, CancellationToken)` waits for the shared queue, not one native detector run.

None is documented as native intro or credits marker detection, and none returns a run ID or exact marker receipt.

### `MediaBrowser.Controller.Library.ILibraryManager`

`GetIntros(BaseItem, User, IntrosOptions)` returns `Task<IEnumerable<Video>>`. This is playback intro media discovery, not chapter-marker generation. It does not trigger or identify native marker detection.

### `MediaBrowser.Controller.Library.IIntroProvider`

`GetIntros(BaseItem, User)` returns `Task<IEnumerable<IntroInfo>>`, where `IntroInfo` contains only intro media path and item ID. It is not the native chapter-marker detector and returns no chapter output receipt.

### Other visible state

- `IItemRepository.GetChapters(...)` reads a chapter snapshot only. A before and after delta is prohibited as provenance.
- `IItemRepository.GetIntroDetectionFailureResult(long)` reads a failure string without starting or identifying a detector run.
- `IItemRepository.LogIntroDetectionFailureFailure(long, long)` writes failure state without an invocation receipt.
- `InternalItemsQuery.HasIntroDetectionFailure` is a query filter for existing state. It is not a detector invocation API.
- `ILibraryManager.QueueLibraryScan()` is broad and unscoped.

## Capability result

| Requirement | Result |
| --- | --- |
| One selected item only | Unsupported |
| Exact invocation completion | Unsupported |
| Exact generated-marker receipt | Unsupported |

Overall: `IsSupported = false`.

The plugin therefore fails closed. No contribution capture, preview, approval, persistence, UI, or submission transport may be implemented under issue #28's safety requirements. The only safe implementation is the explicit unsupported capability model.
